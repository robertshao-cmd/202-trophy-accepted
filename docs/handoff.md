# 發票推理局 — 開發交接文件（Claude Code 用）

黑客松當日目標：做出一場 **6–8 人可完整順跑的三幕推理局** Web MVP，現場 demo 供評審掃碼入局。
一句話定位：Kahoot 的底層邏輯 × 偵探辦案的皮 × 真實發票當證據的多人搶答遊戲。

## 1. 遊戲總覽（三幕結構）

一個案件 = 系統暗中選定一名玩家為「真兇」＋他真實的某一天 3–5 張發票。

```
[建局] → [入局/等待室] → 第一幕(犯罪現場) → 第二幕(口供審訊) → 第三幕(終局指認) → [結案結果頁]
```

- **第一幕 犯罪現場**（每張發票 1 題，共 3–5 題）：污漬遮蔽的發票，玩家推理「消費地點」。答對 → 污漬擦除、發票歸位證據板
- **第二幕 口供審訊**（4 輪）：每輪綁定一個第一幕解碼出的商家。3 名玩家上台各唸一句口供（2 真 1 假），台下投票誰說謊。說謊者列入嫌疑名單
- **第三幕 終局指認**：行動線按真實時間戳動畫播放 → 首輪下注 → 亮決定性線索 → 末輪下注 → 開牌真兇 → 結案回放

## 2. 案件包 JSON Schema

```
cases[]:
  owner        真兇（僅系統/主持視角可見，絕不可下發到玩家端 payload）
  date         案發日
  confusable   可混淆度（幾名玩家同為相關商家常客）
  invoices[]:  {time, brand, reg_name, addr, amt, items[]}  # 已按真實時間排序
  act1[]:      {invoice_idx, type, prompt, options[4], answer, 遮蔽說明?}
               # type ∈ 品名分類推店家 / 登記名破解 / 通路小分類推店家
  act2[]:      {round, theme(商家), members[3], liar, 旁白,
                statements[]: {player, stmt, is_lie, note}}
  act3:        {reveal, first_bet, final_clue, final_bet, escape_bonus}
```

**安全鐵則：`owner`、`is_lie`、`answer` 只存在伺服端狀態，任何玩家端 API response 都不得包含**（開發時最容易犯的錯，驗收會查 network payload）。

## 3. 遊戲流程細節與計時

| 環節 | 規格 |
|---|---|
| 建局 | 主持人選案件（從案件包挑）→ 產生 QR/連結 |
| 入局 | 掃碼 → 輸入偵探代號 → 選擇自己身分（對應 CSV 人名）→ 等待室。4 人以下不可開局，9 人以上拒絕 |
| 第一幕答題 | 每題倒數 20 秒，4 選 1。揭曉停 6–8 秒：先亮正解，再翻「證據卡」（擬真發票樣式：商家/品項/金額/時間，發票號碼只顯示後 4 碼） |
| 第二幕口供 | 每輪：旁白 → 3 句口供逐句顯示（現場由本人唸出）→ 台下 20 秒投票（台上 3 人不投）→ 揭曉說謊者＋開證據卡驗證 → 嫌疑名單 +1 |
| 第三幕 | 行動線動畫（每站停 2 秒）→ 首輪下注 15 秒 → 亮 final_clue → 末輪下注 15 秒 → 開牌 → 結案回放（各偵探押注史 + 真兇在第二幕的謊言與打臉發票並排展示） |

### 計分（三軌）

| 軌 | 規則 |
|---|---|
| 答題分 | 第一幕答對 100 + 剩餘秒數×5；第二幕投中說謊者 +100 |
| 下注分 | 首輪押中真兇 400；末輪押中 150。押錯 0 分不倒扣 |
| 潛逃分（真兇專屬） | 第二幕自己那輪未被過半投中 +150；首輪下注未被過半押中 +150 |

排行榜每環節結束後更新，顯示 top 5 + 自己名次，停 3 秒。

### 結案結果頁（P0）

全組戰績卡：冠軍偵探、真兇潛逃成績、一個聚合驚喜數字（如「本局嫌疑人合計造訪超商 XXX 次」，從 pools 統計挑最大值）、CTA「開新案件，考你的朋友」。

## 4. 技術決策（已拍板，不要重新發明）

- 單一 Web App，**雙視圖**：主持畫面（大螢幕投影：題目/證據板/行動線動畫）＋玩家畫面（手機直式：作答/下注）
- 同步：**2 秒輪詢**房間狀態（`GET /room/:id/state`），不用 WebSocket
- 狀態全放**伺服端記憶體**，不用 DB。局結束即清
- 斷線容錯：玩家中途關頁/斷線 → 缺答按未作答處理，**局不能崩**
- 後端任選 Node 或 Python 單檔起得來的框架；前端手機端優先，不用打包工具也行
- 案件在**開局前一次性載入**選定的 case，runtime 不呼叫編譯器

## 5. 視覺（偵探皮，上限 1.5 小時）

- 深色底、檔案袋、紅線圖釘、「機密」章；文案偵探腔但好笑（範例：「證據顯示，嫌疑人本季造訪 50 嵐達 17 次。辯方律師已放棄辯護」）
- 命名對照：房間=案件#編號、玩家=偵探/嫌疑人、題目=案情、發票=證據、揭曉=開牌、真話者=路人
- 污漬遮蔽 → 答對後擦除動畫（CSS 遮罩即可，別做太重）
- **玩法跑順永遠優先於皮**。皮最後 1.5 小時再上

## 6. 開發順序（照做）

1. 房間骨架：建局/入局/等待室/輪詢狀態機
2. 第一幕循環：出題 → 倒數 → 作答 → 揭曉證據卡 → 計分 → 排行榜
3. 第二幕：口供顯示 → 投票 →揭曉 → 嫌疑名單
4. 第三幕：行動線動畫 → 兩段下注 → 開牌 → 結案頁
5. 全流程串測 ×2（含一人中途斷線）
6. 偵探皮
7. （P1，有餘裕才做）個人稱號卡×3：人形監視器/頭號神秘人物/最沒有自知之明

**砍單順序（時間不夠由上往下砍）**：稱號卡 → 行動線動畫改靜態圖 → 第一幕減至 3 題。第二幕 4 輪不可砍——主題輪是遊戲靈魂。

## 7. 驗收清單（demo 前自測）

- [ ] 建局 → 8 人掃碼入局 → 開局，全程 < 2 分鐘
- [ ] 三幕連跑無卡死；倒數、投票、下注、揭曉循環正常
- [ ] 玩家端 network payload 不含 owner / is_lie / answer
- [ ] 第二幕台上 3 人被鎖定不可投票；本人視角顯示「大家怎麼看你」
- [ ] 一人中途關頁，局繼續跑
- [ ] 結案頁完整：押注史回放 + 真兇謊言打臉畫面 + CTA
- [ ] 全局實測時長 ≤ 13 分鐘

## 8. 隱私規則（已在編譯器處理，勿繞過）

- 商家白名單（超商/超市量販/連鎖餐飲/咖啡手搖/外送/小吃）＋品項黑名單（個人清潔/醫療等關鍵字）已在編譯階段過濾
- **開局前必須人工過一遍該案件的 `案件腳本.md`**——特別是跨縣市地址（如高雄左營）這種強線索，需當事人同意公開到縣市層級
- 內部 demo 用同仁發票，使用前口頭 opt-in

## 9. 已知調整選項（不做也能 demo）

- 犯人輪「三人同詞」強制版：把該輪 3 句口供都換成同一句不在場證明，純比誰演技好（編譯器 `act2_rounds` 內小改）
- 金額競猜正解隨機落位已處理；口供模板同輪去重未處理（機率低，人工審核可攔）
